# Study

AI 에이전트 시대에 개발자가 무엇을 공부하고 어떤 역할로 옮겨가야 하는지 정리한 학습 노트입니다. 특정 도구 사용법이 아니라, 도구가 바뀌어도 남는 원리와 판단 기준을 다룹니다.

2026년 9월, 하네스 엔지니어링 이후의 흐름을 묻는 대화에서 시작했습니다. 트렌드 정리에서 출발해 개발자 역할의 변화, 준비할 것, 구체적인 공부 목록까지 이어집니다.

## 문서

- [01 AI 엔지니어링 트렌드의 계보](concepts/01-ai-engineering-trends.md) — 프롬프트, 컨텍스트, 하네스, 루프, 그래프 엔지니어링의 흐름과 다음 단계 예측
- [02 개발자 역할의 변화와 준비](concepts/02-developer-role-shift.md) — 코드를 쓰는 사람에서 시스템을 책임지는 사람으로, 준비할 다섯 가지와 익히는 방법
- [03 공부 목록: 코드 아래 층](concepts/03-study-roadmap-core.md) — HTTP, Linux, 네트워크, DB 등 지금 업무에서 바로 쓰이는 기반 원리
- [04 공부 목록: 더 넓은 기반](concepts/04-study-roadmap-extended.md) — 컴퓨터 동작, 런타임, 분산 시스템, 보안, 설계 등 더 큰 시스템을 맡을 때 필요한 것

## 읽는 순서

01과 02는 방향을 잡는 글이라 한 번 읽으면 됩니다. 03과 04는 목록이라 문제가 생겼을 때 해당 항목을 찾아 파는 식으로 씁니다. 전부 읽는 것이 목표가 아니라, 문제가 났을 때 어느 서랍을 열어야 하는지 아는 것이 목표입니다.
