# 공부 목록: 더 넓은 기반

## 학습 목표

- [03 코드 아래 층](03-study-roadmap-core.md)이 지금 터지는 문제용이라면, 이 목록은 더 큰 시스템을 맡거나 원인을 더 깊이 보게 될 때를 위한 것입니다.
- 수익이 큰 순서로 정리해 어디서부터 시작할지 정합니다.

## 1. 컴퓨터가 실제로 돌아가는 방식

- 메모리. 스택과 힙, 가비지 컬렉션이 언제 도는지. 웹 앱에서 메모리 누수가 어떻게 생기는지(이벤트 리스너 미해제, 클로저가 잡고 있는 참조). 컴포넌트 unmount 시 리스너를 지우는 이유가 여기 있습니다.
- CPU와 스케줄링. 프로세스와 스레드의 차이, 컨텍스트 스위칭. 코어가 4개인데 서버가 왜 느린지.
- 파일 I/O와 버퍼. 디스크 읽기가 메모리보다 얼마나 느린지 감으로 아는 것. 성능 판단의 기준이 됩니다.
- 문자 인코딩. UTF-8이 무엇인지. 한글이 깨지는 원인 종류(인코딩 불일치, 정규화 NFC와 NFD, 맥에서 만든 파일명이 리눅스에서 다르게 보이는 이유).
- 시간. UTC와 로컬 시간, 타임존과 서머타임. 서버와 브라우저 시간이 다를 때 생기는 버그. Unix 타임스탬프. 예약이나 진료시간 기능이 있으면 반드시 만납니다.
- 부동소수점. 0.1 + 0.2가 왜 0.3이 아닌지. 금액 계산을 float로 하면 안 되는 이유.

확인: "이 페이지 오래 열어 두면 느려져요"를 듣고 개발자 도구 메모리 탭에서 원인을 찾을 수 있는가.

## 2. 자료구조와 알고리즘, 실용 수준만

코딩 테스트용이 아니라 "이 코드가 데이터 만 건에서도 괜찮은가"를 판단하는 수준입니다.

- 배열, 해시맵, 셋, 트리의 성질과 각 연산의 대략적인 비용. 중첩 반복문이 왜 위험한지.
- 정렬, 검색, 그래프 순회의 기본 개념. 지도 검색 기능이면 공간 인덱스(geohash, R-tree)가 왜 필요한지.

확인: 리스트 필터링 코드를 보고 "데이터 늘면 느려진다"를 실행 전에 알 수 있는가.

## 3. 언어 런타임

- JavaScript 엔진. 이벤트 루프의 정확한 순서(마이크로태스크와 매크로태스크). Promise가 실제로 언제 실행되는지. `await`가 무엇을 양보하는지.
- 모듈 시스템. ESM과 CommonJS의 차이. 번들러가 tree shaking을 어떻게 하는지. 순환 참조가 왜 undefined를 만드는지.
- 타입 시스템. TypeScript의 타입이 런타임에 없다는 것의 의미. 구조적 타이핑. 제네릭이 해결하는 문제.
- 반응성. Vue의 ref와 reactive가 Proxy로 어떻게 동작하는지. computed가 언제 재계산되는지. 어떤 변경이 왜 화면에 안 반영되는지.

확인: "버튼 두 번 눌러야 반영돼요"를 듣고 반응성 문제인지 비동기 순서 문제인지 가를 수 있는가.

## 4. 분산 시스템 기초

- 서버가 둘 이상일 때 생기는 일. 세션이 한 서버에만 있는 문제, 캐시 불일치. 배포 중 구버전과 신버전이 동시에 도는 순간.
- 멱등성. 같은 요청이 두 번 와도 안전하게 만드는 법. 결제, 예약, 접수에 필수입니다.
- 타임아웃과 재시도. 재시도가 오히려 장애를 키우는 경우. 백오프, 서킷 브레이커.
- 메시지 큐. 왜 바로 처리하지 않고 큐에 넣는지. 순서 보장과 중복 처리.
- 캐시 계층. Redis 같은 것이 어디에 놓이고 무효화를 어떻게 하는지. "캐시 무효화는 어려운 문제"라는 말의 실제 의미.

확인: "가끔 예약이 두 번 잡혀요"를 듣고 재현 조건과 방어 방법을 설계할 수 있는가.

## 5. 보안

- 웹 공격 유형. XSS, CSRF, 오픈 리다이렉트(`target` 파라미터를 허용 도메인으로 제한하는 이유), SQL 인젝션, 경로 탐색.
- 인증과 인가의 차이. 로그인했다는 것과 이 데이터를 볼 권한이 있다는 것은 다릅니다.
- 비밀 관리. 환경변수, 시크릿이 git에 들어가면 생기는 일. 클라이언트 번들에 박힌 키는 공개된 것과 같다는 사실.

확인: PR 리뷰에서 사용자 입력이 어디로 흘러가는지 따라가며 위험 지점을 짚을 수 있는가.

## 6. 설계와 구조

- 결합도와 응집도. 한 곳을 바꾸면 어디까지 영향이 가는지 예측하는 감각.
- 경계 설정. 어디를 모듈로 자를지, API 계약을 어떻게 정할지, 하위 호환을 언제 지켜야 하는지.
- 상태 관리. 상태가 어디 살아야 하는지(URL, 스토어, 컴포넌트, 서버). 상태 중복이 버그의 근원인 이유.
- API 설계. REST의 실제 의미, 에러 응답 형식, 페이지네이션, 버전 관리.

확인: 기능 요청을 받았을 때 코드를 열기 전에 "어디를 건드려야 하고 무엇이 영향받는지"를 말할 수 있는가.

## 7. 도구의 내부

- git 내부. 커밋이 스냅샷이라는 것. 브랜치는 포인터일 뿐이라는 것. 머지와 리베이스가 실제로 하는 일. reflog로 거의 모든 것을 복구할 수 있다는 것. force push 상황에서 겁이 안 나려면 이것을 알아야 합니다.
- 컨테이너. Docker 이미지와 컨테이너의 차이, 레이어, 볼륨. 로컬에서는 되는데 컨테이너에서는 왜 안 되는지.
- CI/CD. 파이프라인 각 단계가 무엇을 보장하는지. 빌드 재현성. 캐시가 깨지면 생기는 일.

확인: 파이프라인 정의를 읽고 배포가 실패했을 때 어느 단계인지 바로 찾을 수 있는가.

## 8. 모바일 플랫폼

앱 웹뷰를 다룬다면 필요합니다.

- iOS와 Android 웹뷰의 차이. 쿠키와 저장소 분리 여부, 자바스크립트 브릿지 방식. 딥링크와 유니버설 링크와 앱 링크의 차이와 검증 파일(assetlinks.json, apple-app-site-association).
- 앱 생명주기. 백그라운드 전환 시 웹뷰에 무슨 일이 생기는지. visibilitychange가 언제 안 오는지.
- 스토어 정책. 웹뷰만 감싼 앱이 왜 심사에서 걸리는지. 업데이트 강제 정책.

확인: "앱에서는 되는데 사파리에서는 안 돼요"를 듣고 차이 목록에서 후보를 고를 수 있는가.

## 9. 관측과 성능

- 프로파일링. 브라우저 Performance 탭, 서버 CPU 프로파일, 느린 쿼리 로그. 추측이 아니라 측정으로 병목을 찾는 습관.
- 지표. p50과 p99의 차이. 평균이 왜 거짓말하는지. 에러율과 처리량.
- 분산 추적. 요청 하나가 여러 서비스를 거칠 때 어디서 시간이 갔는지 보는 법.

확인: "느려요"를 받았을 때 첫 행동이 코드 수정이 아니라 측정인가.
