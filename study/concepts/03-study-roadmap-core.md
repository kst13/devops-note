# 공부 목록: 코드 아래 층

## 학습 목표

- 웹 프론트엔드, 앱 웹뷰, nginx, Linux 서버, MySQL을 다루는 개발자가 먼저 익힐 기반 원리를 우선순위대로 정리합니다.
- 각 항목이 익혀졌는지 확인하는 질문을 갖습니다.
- 전부 읽는 것이 아니라 문제가 났을 때 어느 항목을 열어야 하는지 아는 것을 목표로 합니다.

## 왜 코드 아래 층인가

프레임워크 사용법은 에이전트가 더 잘 압니다. 문제가 났을 때 원인을 가르는 기준은 그 아래 원리입니다. 쿠키가 두 도메인 사이에 왜 공유되지 않는지, 호스트명이 바뀌었을 때 옛 프로세스가 왜 옛 경로에 계속 쓰는지는 전부 이 층의 이야기입니다. 이 목록의 절반만 알아도 흔한 운영 문제 대부분은 에이전트 없이 원인을 짚을 수 있습니다.

## 1순위. HTTP와 브라우저

지금 업무의 8할이 여기서 깨집니다.

- HTTP 요청과 응답 구조. 메서드, 상태 코드의 의미(301과 302와 307, 401과 403, 502와 504), 헤더가 하는 일.
- 쿠키. Domain, Path, SameSite, Secure, HttpOnly, Max-Age 각각의 효과. 등록 가능 도메인(PSL) 개념. 서로 다른 등록 도메인 사이에 쿠키가 넘어가지 않는 이유.
- 캐시. Cache-Control, ETag, 브라우저 캐시와 프록시 캐시의 차이. "배포했는데 안 바뀌어요"의 원인들.
- CORS와 동일 출처 정책. preflight가 언제 나가는지, credentials 옵션이 쿠키에 미치는 영향.
- 리다이렉트와 URL. 서버 리다이렉트와 JS 리다이렉트의 차이, `location.replace`와 `href`의 차이, 히스토리 스택, 딥링크와 intent 스킴.
- 브라우저 렌더링 순서. HTML 파싱 중 스크립트가 어떻게 실행되는지, `defer`와 `async`, 인라인 스크립트가 SyntaxError 하나로 통째로 죽는 이유.
- 웹뷰. 앱 안 브라우저가 일반 브라우저와 다른 점(UA, 쿠키 저장소, 브릿지, visibilitychange 동작).

확인: "모바일 사파리에서 웹으로 보기를 눌렀는데 다른 채널 사이트로 가면 다시 안내 페이지가 뜹니다"를 듣고 원인 후보 세 개를 바로 말할 수 있는가.

## 2순위. Linux 프로세스와 파일시스템

서버 문제의 대부분입니다.

- 프로세스. PID, 부모와 자식, 시그널(TERM, KILL, HUP, USR1). 데몬이 재실행될 때 인자와 환경변수가 어디서 오는지.
- systemd. unit, service, timer의 관계. enabled와 active의 차이. journalctl로 로그 보기.
- 파일시스템. 권한과 소유자, 심볼릭 링크, 마운트, inode. 삭제한 파일을 프로세스가 잡고 있으면 용량이 안 줄어드는 이유. du와 df가 다르게 나오는 이유.
- 로그 관리. logrotate 동작, 로그가 왜 무한히 쌓이는지, 압축과 보관 정책.
- 셸. 파이프, 리다이렉션, 종료 코드, 환경변수 전파, cron. 스크립트를 쓰는 것이 아니라 읽을 수 있으면 됩니다.
- 패키지와 의존성. lockfile이 하는 일. node_modules가 lockfile과 어긋날 때 생기는 일.

확인: `/var/log`가 꽉 찼다는 알림을 받았을 때 검색 없이 10분 안에 범인을 찾을 수 있는가.

## 3순위. 네트워크와 프록시

nginx 설정을 이해하려면 필요합니다.

- DNS. 도메인이 IP로 바뀌는 과정, TTL, 로컬 hosts 파일. 서버에서 resolver 설정이 왜 필요한지.
- TLS. 인증서 체인, 와일드카드 인증서, SNI(`proxy_ssl_server_name`이 이것). 프로토콜 버전과 암호 스위트가 왜 문제가 되는지.
- 리버스 프록시. Host 헤더와 X-Forwarded-For가 왜 필요한지. 업스트림에서 클라이언트 IP를 어떻게 아는지. proxy_redirect가 하는 일.
- nginx 동작 원리. location 매칭 우선순위(`=`, `^~`, `~`, 접두어). map이 요청마다 어떻게 평가되는지. `if`가 왜 위험한지.
- 포트, 방화벽, 로드밸런서. 요청이 브라우저에서 서버 프로세스까지 거치는 경로를 그림으로 그릴 수 있는 수준.

확인: 회사 nginx 설정을 처음 보는 사람에게 "요청이 어디로 가는지" 설명할 수 있는가.

## 4순위. DB

기능이 느려지거나 데이터가 꼬일 때 필요합니다.

- 인덱스. B-tree가 무엇인지, 복합 인덱스의 컬럼 순서가 왜 중요한지, EXPLAIN 읽는 법.
- 트랜잭션과 격리 수준. 동시에 두 요청이 같은 행을 건드리면 무슨 일이 생기는지. 데드락.
- 조인과 N+1. ORM이 뒤에서 몇 번 쿼리하는지 보는 습관.
- 스키마 설계. 정규화의 목적, 언제 깨도 되는지. 마이그레이션이 운영 중 테이블에 미치는 영향.

확인: 느린 화면 하나를 받아 쿼리 로그와 EXPLAIN으로 원인을 짚을 수 있는가.

## 5순위. 나머지, 필요할 때

- 인증. 세션과 토큰(JWT)의 차이, OAuth 흐름. 토큰이 어디 저장되고 어떻게 탈취되는지.
- 동시성. 이벤트 루프, 비동기가 실제로 무엇을 기다리는지. 타이머와 visibilitychange 같은 이벤트 순서.
- 빌드와 배포. 번들러가 하는 일. 환경변수가 빌드 시점에 박히는지 런타임에 읽히는지(`%VITE_APP_...%` 치환이 이것). CI 파이프라인의 각 단계.
- 관측. 로그, 메트릭, 트레이스의 차이. 문제가 생겼을 때 어디를 먼저 보는지.
