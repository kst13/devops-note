# Kafka 플랫폼 포트 정리

> 서버 3대는 동일 대역이라 **서버 간 통신은 방화벽 신청 불필요** — 신청이 필요한 것은 개발자·관리자 접근 포트뿐입니다. 배치 방안(A/B) 확정 시 "대상 서버"의 실제 IP를 확정합니다.

## 현재 운영 중

| 포트 | 서비스 | 보안 | 접근 주체 | 방화벽 신청 |
| --- | --- | --- | --- | --- |
| 9092 | 브로커 간 복제 (INTERNAL) | SASL_SSL | 서버 간 | 불필요 (동일 대역) |
| 9093 | KRaft 컨트롤러 쿼럼 | SSL (mTLS) | 서버 간 | 불필요 (동일 대역) |
| 9094 | **Kafka 앱 접속 (CLIENT)** | SASL_SSL | 개발자·앱, 관리자 | **필요** — 서버 3대 모두 (`bootstrap.servers`에 3대 기재) |
| 8081 | **Schema Registry** | HTTP (인증 없음) | 개발자·앱, 관리자 | **필요** — SR 2대 (클라이언트가 두 주소 나열) |

## 구현 예정

| 포트 | 서비스 | 보안 | 접근 주체 | 방화벽 신청 |
| --- | --- | --- | --- | --- |
| 8083 | Kafka Connect REST (커넥터 등록·관리) | HTTP (인증 없음) | 관리자 | **필요** — Connect 2대, 관리자 IP 한정 (DB 접속정보 취급) |
| 7071 | JMX Exporter (브로커 메트릭) | HTTP | 서버 간 (Prometheus 수집) | 불필요 (동일 대역) |
| 9308 | kafka_exporter (컨슈머 lag 메트릭) | HTTP | 서버 간 (Prometheus 수집) | 불필요 (동일 대역) |
| 9090 | Prometheus (메트릭 조회·타깃 상태) | HTTP (인증 없음) | 관리자 | **필요** — 모니터링 서버 1대, 관리자 IP 한정 |
| 3000 | Grafana (대시보드) | HTTP + 로그인 | 개발자, 관리자 | **필요** — 1대. lag 대시보드는 서비스팀도 보므로 개발자 대역 포함 권장 |
| 9095 | Alertmanager (알람 라우팅) — **기본 9093에서 변경** | HTTP | 서버 간 | 불필요 (동일 대역) |
| 8080 | Kafka UI (클러스터 조회·관리) | HTTP + 로그인 | 관리자 | **필요** — 1대, 관리자 IP 한정 (토픽 삭제 가능 도구) |
| 미정 | Admin Portal (자체 관리 포털) | HTTP + 로그인 | 용도에 따라 | **필요** — 개발자 창구면 개발자 대역, 관리자용이면 관리자 IP 한정 |

### 주의사항

- **포트 충돌**: Alertmanager 기본 포트(9093)는 KRaft 컨트롤러가 사용 중 — 호스트 네트워크로 같은 서버에 올리면 기동 실패. `--web.listen-address=:9095`로 변경해서 배치.
- **인증 없는 HTTP 4종**(8081 · 8083 · 9090 · 9308)은 방화벽 제한이 유일한 보호막 — 특히 8081(스키마 등록·삭제 가능)과 8083(커넥터 조작 가능)은 반드시 대역 제한.

## 방화벽 신청 요약

| 신청 대상 | 포트 |
| --- | --- |
| 개발자·앱 서버 대역 | 9094 ×3대 · 8081 ×2대 · [선택] 3000 ×1대 |
| 관리자 IP | 위 전부 + 8083 ×2대 · 9090 ×1대 · 8080 ×1대 · Admin Portal ×1대 |

서버 간 전용 포트(9092 · 9093 · 7071 · 9308 · 9095)는 동일 대역 내 통신이므로 신청 대상 아님.
