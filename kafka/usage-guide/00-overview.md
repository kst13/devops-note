# Kafka 사용 가이드 — 개요

> 이 클러스터를 안전하게 함께 쓰기 위한 **개발자용 사용 가이드 시리즈**입니다. 이 폴더 하나로 완결되도록 작성했으므로, 폴더째 복사해 다른 저장소에서 그대로 사용할 수 있습니다. 샘플 코드는 **Java + Spring Boot(Spring Kafka)** 기준입니다.

## 전제 조건

- 클러스터: 브로커 3대, 모든 토픽 **RF3(복제 3) + `min.insync.replicas=2`** 표준.
- 접속: 서비스별 발급 계정(SCRAM) + TLS. 로컬 개발은 PLAINTEXT 허용.
- 애플리케이션: Java 21 + Spring Boot(Spring Kafka), 메시지 값은 JSON.

## TL;DR — 이것만 지키면 됩니다

- ✅ 토픽은 **직접 만들지 말고 요청**하세요 → [02 토픽 요청하기](02-topic-request.md)
- ✅ 토픽 이름은 **`<도메인>.<엔티티>.<이벤트>` 3단계 고정** → [01 토픽 명명 규칙](01-topic-naming.md)
- ✅ 프로듀서는 **`acks=all` + `enable.idempotence=true`** → [03 프로듀서](03-producer.md)
- ✅ 순서가 중요하면 **메시지 key**를 지정하세요 → [03 프로듀서](03-producer.md)
- ✅ 프로듀서는 **`compression-type: lz4`** 로 압축해서 보내세요 → [03 프로듀서](03-producer.md)
- ✅ 컨슈머는 **수동 커밋**(처리 후 `ack.acknowledge()`) → [04 컨슈머](04-consumer.md)
- ✅ 컨슈머는 **같은 메시지를 두 번 받아도 안전**하게(멱등) 처리하세요 → [04 컨슈머](04-consumer.md)
- ✅ **자기 서비스 계정**으로만 접속하고, `bootstrap.servers`에 **브로커 3대를 모두** 적으세요 → [05 접속 설정](05-connection-config.md)

## 핵심 원칙 (운영 정책)

| 원칙 | 의미 | 왜 |
| --- | --- | --- |
| 안전 기본값 | 모든 토픽 **RF3 + `min.insync.replicas=2`**, 프로듀서 **`acks=all`** | 브로커 1대가 죽어도 커밋된 메시지는 유실되지 않습니다. 셋 중 하나라도 빠지면(예: `acks=1`) 리더 장애 시 유실이 생깁니다 |
| 최소 권한 | 서비스마다 **별도 계정**, 자기 토픽만 접근 | 사고 범위를 자기 서비스로 한정합니다. 계정을 공유하면 누가 보냈는지 추적도 안 됩니다 |
| 거버넌스 | **토픽 자동 생성 금지**, 명명 규칙에 맞춰 명시적으로 생성 | 오타 토픽·무관리 토픽이 쌓이는 것을 막고, 모든 토픽에 표준 설정(RF3 등)을 강제합니다 |
| 관측 | 컨슈머 **lag**·복제 상태를 모니터링 | lag 증가와 ISR 축소는 장애의 조기 신호입니다. 문제는 커지기 전에 잡습니다 |

이 원칙은 여러분이 실수로 데이터를 잃거나 남의 토픽을 건드리는 걸 막기 위한 것입니다.
